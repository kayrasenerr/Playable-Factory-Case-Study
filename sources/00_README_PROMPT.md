# Playable Factory PM case: research and execution folder

Prepared 2 October 2026. This is a research-backed working kit and implementation guide, not a completed case submission. It preserves the manual's requirements, provides researched starting directions, calculates Task 5.2, and tells an execution AI precisely what to produce and verify.

## Start here

1. Read `01_Case_Requirements.md` and `14_Sources_and_Evidence.md`.
2. Give your execution AI this entire folder, including the two source PDFs, and paste `MASTER_PROMPT.md` into its conversation.
3. Ask it to execute the case, not merely summarize these guides. If its file limit is restrictive, upload the original PDFs, master prompt, requirements and source register first, then the task guides in task order.
4. Maintain the evidence ledger and AI log as work happens. Review the three exact linked playables before accepting Task 3.
5. Export the final submission as one PDF/deck, respecting each task's length cap. This research folder is supporting material, not the intended recruiter-facing output.

## Evidence status

- **Verified:** manual requirements; eight supplied data rows; arithmetic; the public product descriptions identified in the source register.
- **Proposed:** company priorities, creative concepts, feature design, outreach sequence, test choices and working schedule. These are our recommendations, not established client needs.
- **Still required for final execution:** dated US/European UA evidence for five eligible studios, current ownership/size checks, ten resolved company LinkedIn pages, observation of the three interactive exports, and genuine human decisions for the AI log.
- **No API access was used:** Task 5.3 is an architecture under the brief's hypothetical access assumption.

Do not relabel a research seed as a qualified prospect. Do not relabel a suggested playable improvement as an observed defect. The task guides deliberately distinguish these states so the final case remains defensible.

## Recommended coherent direction

Use a puzzle studio and an app-based European grocery service as the two Task 1 opportunities. Prefer a small, easily demonstrated mechanic for the game; use a shopping-list mini-game for the grocery brand. Choose Ready for Task 2 and propose a goal-aware experiment setup and QA layer. Use the same commercial distinction throughout: games acquire players; grocery services acquire first orders and, eventually, repeat profitable customers. Reuse research where it helps, while keeping the fictional campaign clients in Task 5.2 separate from real companies.

This coherence is an editorial choice, not a manual requirement. Do not imply that Picnic or any selected studio is an existing PF client, or that their results are represented by the fictional datasets.
